## 三、⚠️ 必须保留的边界说明（重写时**不许删**）

1. **pool 法的 recall 绝对值偏高**（池外相关块统计不到）→ 该指标**只看相对变化**
2. **20 题是小样本自评** → 结论只作趋势参考
3. **相关性标注**经历过：LLM 初标 → 独立盲审（一致率仅 80%）→ 人工裁定 → 金标抽查 8 条；
   **不是全量人工标注**
4. **长回答题尾部延迟超标**（对比类题 22s+）→ 多步题按定稿单独统计
5. **单机单用户**：接口无鉴权、上传未做大小与文件名净化，**请勿暴露公网**
6. **本版不做**：扫描件 OCR / PDF 以外格式 / 向量数据库 / LangChain 版对比
7. **检索的硬伤**：有些题的正确块压根进不了候选池（重排救不了召回）

## 四、可以讲的技术故事（有完整证据链）

| 故事 | 一句话 |
|---|---|
| **双通道强制预取** | 模型会跳过工具凭记忆编答案 → 改成由代码保底取料 |
| **8 档检索实验** | 尝试了关键词改写、去公司名、规则式上下文、LLM 上下文、重排、两两组合 |
| **两条反直觉结论** | ①「加信息」不是优化，「加**有区分度**的信息」才是；② 两个有效优化会**互相抵消** |
| **指标会骗人** | 旧口径下最优的配置，在金标口径下最差 → 先确认尺子量的是你要的东西 |
| **10 倍单位换算** | 修法不是加提示词，而是**让数据自带换算结果**（从源头消除心算） |
| **MySQL 双后端** | 与其在适配层翻译方言，不如把业务 SQL 限定在两库公共子集里 |
