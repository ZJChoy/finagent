# Prompt 策略

> 本项目用的是**自研编排**，所以 Prompt 不是"一段魔法文字"，而是一份**逐条可追溯的规则集**。
> 本文记录：每段 Prompt 长什么样、每条规则是为了防什么事故、以及上下文是怎么组装的。

---

## 一、上下文组装顺序

一次问答送给模型的消息，顺序是固定的：

```
[system] 系统提示词（配置页可改）
         └─ 末尾附：长期记忆（L4，≤300 token）
         └─ 末尾附：本会话更早内容的摘要（L2，滚动压缩）
[user/assistant …] 最近若干轮原文（条数由 keep_recent 控制）
[user] 本轮问题
       └─ 末尾附：本轮系统预取的资料（通道 A / 通道 B）
```

三条纪律：

1. **两条通道必须分开放** —— 年报原文与结构化数据的可信度不同，混在一起读者分不清数字出处。
2. **引用编号只在本轮有效** —— 历史里的 `（片段 N）` 在送进模型前会被**剥掉**（见下）。
3. **摘要与长期记忆都不占"原文"的位** —— 它们是压缩/提炼后的结果，不参与 `keep_recent` 计数。

## 二、系统提示词（全文）

```
你是一名严谨的上市公司财报分析助手。

系统会在消息末尾附上**本轮预取的资料**，分两条通道：
- 通道 A｜年报原文片段（本地检索，带文件名与页码）→ 引用时写（A-片段 N）
- 通道 B｜结构化财务数据（akshare，字段与期间明确）→ 引用时写（B）

回答规则：
1. 涉及公司事实或数字时，必须严格依据上面预取的资料，不得凭记忆作答；
   资料里没有的，就直说"未找到相关依据"。
2. 每个结论后都要标出依据来自哪条通道：通道 A 写（A-片段 N），通道 B 写（B）。
3. 预取资料不够时可以补充调用工具（直接调用，不要输出"我来查一下"这类过程说明）：
   search_knowledge / get_stock_financials / calculate
4. 预取资料里没有「片段 N」时，回答里绝不允许出现该字样 —— 那是伪造引用。
5. 数字要说明口径（单位、期间）。单位换算（元/万元/千元/亿元）必须调用 calculate 验算，不要心算；
   结构化财务数据里已经给出换算结果，优先直接采用。
6. 不给投资建议，只呈现事实与依据。
7. 回答简洁直接，不要长篇铺陈；除非用户明确要求详细展开。
```

## 三、逐条规则的来历

| 规则 | 防的事故（都是实测踩到的） |
|---|---|
| **1 必须有依据** | 模型对"美的 2025 营收"**跳过工具凭记忆答**，甚至断言"尚未发布 2025 年报"（语料里明明有） |
| **2 标注来源通道** | 用户指出："有依据，但没说清依据来源" —— 同题数字可能来自年报文本或结构化接口，必须能分辨 |
| **3 直接调用工具，别叙述** | 模型会输出"我需要检索……让我使用 search_knowledge"，这段叙述**被当成正文混进答案** |
| **4 禁止伪造引用** | 多轮追问时模型**没检索却写「片段 3」**（被历史里的编号诱导），直接违反"幻觉率 <5%" |
| **5 换算必须走工具** | `172,054,171,890.91 元` 被写成「172.05 亿元」—— **10 倍错误**  |
| **6 不给投资建议** | PRD 的越界处理：只呈现事实与依据 |
| **7 回答简洁** | 长回答会顶到「完成延迟 P95 < 20s」的上限（实测单题最长 17s） |

## 四、引用约定：为什么用编号

注入块的形态：

```
── 通道 A｜年报原文片段（本地向量检索，可核对页码）──
【片段 1】来源：600519_2025_annual.PDF 第 17 页（相似度 0.72）
   …原文…

── 通道 B｜结构化财务数据（akshare，来源识别依据：本地映射「贵州茅台」）──
600519 结构化财务数据（akshare·stock_financial_abstract）
报告期：20260630（最新） / 20251231（年度） / 20241231（年度）
- 营业总收入：20251231 = 172,054,171,890.91 元（≈ 1,720.54 亿元）；…
```

用**编号**而不是让模型自己写文件名，原因有两个：

1. 模型写不准长文件名，容易编；
2. 前端可以把编号映射成**结构化的引用列表**（文件名 + 页码 + 相似度），比让模型抄更可靠。

**一个必须处理的坑**：如果一轮里检索了两次，`search_knowledge` 每次都从「片段 1」开始编号，
编号会撞车。所以循环里会把后续工具返回文本里的编号**整体平移**（倒序替换，避免连锁改名）。

## 五、引用与历史解耦

送模型之前，会把**历史回答里的 `（片段 N）` 标记剥掉**：

```python
_CITE_RE = re.compile(r"[（(]\s*片段\s*\d+(?:\s*[、,，和]\s*片段\s*\d+)*\s*[)）]")
```

理由：上一轮的编号对**这一轮毫无意义**。留着它，模型会"照抄编号" —— 实测它就这么干了，
凭空写出本轮根本不存在的「片段 3」。**引用编号只在本轮有效。**

## 六、几个辅助 Prompt

除了主提示词，还有三处轻量调用（都用 `REWRITE_MODEL`，`max_tokens` 很小）：

| 用途 | 触发时机 | 输出上限 |
|---|---|---|
| **查询改写** | 仅当有历史（多轮追问） | 120 token |
| **会话摘要** | 消息条数超过阈值 | 400 token |
| **长期记忆提炼** | 每积累 N 条用户消息 | 200 token |

**查询改写**的系统提示（防止它自作主张回答）：

```
你是查询改写器。把用户的最新问题改写成一句自包含、可直接检索的问题：
补全主语与指代（如"它""那 2025 年呢""那家公司的"），保留原意，不要扩写。
只输出改写后的问题本身，不要解释，不要回答。
```

效果：`那它的销售渠道呢？` → `贵州茅台的销售渠道是什么？`

**长期记忆提炼**只提炼**关于用户**的信息，不提炼公司信息：

```
从对话中提炼关于用户本人的长期信息（不是公司信息），例如常用公司、回答偏好、习惯口径。
只输出 JSON 数组，每项形如 {"kind":"常用公司","content":"贵州茅台（600519）"}，
kind 只能是：偏好 / 常用公司 / 显示口径。最多 3 项，没有就输出 []。
```

## 七、Prompt 之外的三道硬校验

Prompt 是**软约束**，实测会被忽略（规则 1 就是证据）。所以外层还有三道**代码级**兜底：

| 层 | 机制 | 硬度 |
|---|---|---|
| L1 | 提示词 | 软 |
| L2 | 门控 + 强制预取（由代码取料） | 半硬（启发式） |
| L3 | **引用校验**：回答里的「片段 N」不在本轮 citations 里就报警 | 硬 |
| L4 | **接地校验 + 拒答兜底**：该取料却颗粒无收 → 替换为拒答 | 硬 |

**结论：不要指望提示词保证正确性，它只负责"表达规范"，正确性交给代码兜。**
